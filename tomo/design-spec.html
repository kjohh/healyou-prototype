Interactive Prototype
互動說明

Onboarding：啟動後自動進入 4 頁引導（品牌 → 語音 → 色彩 → Reflection）。最後一頁點擊「開始使用」或任一頁點擊「略過」→ 進入登入選擇。登入後約 2 秒 loading → 直接進入日記簿空狀態

錄音流程

在日記簿點擊「＋ 新增日記」進入錄音畫面 → 點擊麥克風開始 → 水彩情緒效果即時生成，進度環顯示填滿進度 → 填滿後自動彈出完成確認卡 → 確認儲存 → 自動回到日記簿

日記瀏覽

日記簿為登入後首頁。點擊任一日記卡片展開詳情。每篇日記顯示所有偵測到的情緒標籤（可多個），並附水彩畫布快照

視覺效果

背景 Canvas 持續運行水彩動畫。偵測到情緒關鍵字時觸發 Emotion Bloom（有機花瓣多邊形），靜態時為環境 Ambient Blobs（柔和飄移）。新增日記時畫布重設

目前限制（Prototype）

資料不持久化，重整後消失。錄音內容為模擬逐字稿，非真實語音辨識。情緒偵測使用本機關鍵字比對，iOS 實作版將改用 LLM 分析（詳見 UI Spec → 情緒系統）

User Flow

完整操作流程

從 App 啟動到完成一篇日記的完整流程，共 12 個畫面。Onboarding（4頁）→ 登入 → 驗證 → 日記簿（空狀態，登入後首頁）→ 錄音待機 → 錄音中 → 完成確認 → 日記簿（有日記）→ 日記詳情。

Motion · Animation

動畫規格

Ambient Blob（背景水彩）
使用 requestAnimationFrame 驅動，錄音中每 8 幀 spawn 一個，閒置時每 60 幀。最大數量 80 個。生命週期 200–600 幀，消逝時 alpha 逐漸趨零。
Emotion Bloom（情緒反應）
偵測到情緒關鍵字時觸發，在螢幕中央附近 spawn 花瓣形色塊。使用情緒對應色，尺寸比 Ambient Blob 大（r: 40–105px）。最大數量 30 個。
Mic Button Pulse（錄音狀態）
CSS keyframe animation，週期 2s infinite。外光暈從 0 擴散至 16px，顏色 rgba(200,80,60,0.22 → 0)。
View Transitions
Recording view ↔ Diary view：opacity transition 0.45s。Auth overlay → Record view：opacity 0.45s。Modal open：translateY(12px → 0) + opacity，0.3s。
半透明覆蓋（水彩漸淡）
每幀在 canvas 上繪製 rgba(247,242,236, 0.035) 的全畫面覆蓋，使舊色塊自然淡出，形成水彩暈染的漸褪感。
情緒切換過渡
iOS 實作版切換情緒時應以 1–2 秒漸變（非硬切）。Dot color transition: transition: background 1s。
Progress Ring 更新
錄音中每次 STT 字元推進時更新 stroke-dashoffset。transition: dashoffset .4s linear，讓進度平滑前進。填滿（pct=1）時觸發 stopAndSave()，延遲 600ms 後彈出 Done Sheet。
Done Sheet 出現
translateY(100%) → translateY(0)，transition: transform .35s cubic-bezier(.32,0,.15,1)。關閉時反向。背後 canvas 靜止（已停止錄音）。
Reflection 淡入
錄音中偵測到負面情緒時，transcript 區域底部的 ref-area 淡入：opacity: 0 → 1，transition: opacity .8s ease。全文直接顯示，無打字機效果。
Canvas Reset
進入錄音畫面（新增日記）時重設畫布：清除所有 blob，填回 #F7F2EC 底色，接著 16 個 ambient blob 以每 120ms 間隔依序 spawn，形成重新「暈染」的感覺。

Product Requirements

Tomo

心境水彩日記 · iOS App · v0.1 draft · 2026-03-21

一句話定位
一款獨立 iOS 語音日記 App，透過療癒視覺體驗與感恩紀錄，在使用者低潮時以過去的自己的話給予支持。
背景與動機

Tomo 是聊心茶室（HealYou）與外部 AI 工程師合作開發的獨立 iOS App，與主平台分開。

核心洞察：使用者在低潮時往往忘記自己曾經有過的正向感受。Tomo 透過語音記錄感恩時刻，並在偵測到低潮情緒時，主動播放過去自己說過的感恩話語，形成「過去的你支持現在的你」的療癒體驗。

視覺技術決策：原始構想是語音驅動即時繪畫動畫，但技術上卡關已久。Kyle 自行做出 Web prototype 後評估效果良好，因此決策轉向：直接以 Kyle 的 prototype 作為實作基準，讓工程師依此實作，目的是讓 MVP 儘快出去做測試。

使用者情境

使用者在日常情況下對著 Tomo 說話，記錄今天感謝的事情（語音輸入）。某天情緒低落時，打開 App 想記錄，App 偵測到這次的情緒狀態與過去有落差，自動播放過去記錄中感恩的片段，讓使用者聽到「過去的自己」說的話。

功能範圍
In Scope MVP

設計含義（Design Implications）
  • 視覺基調需要有別於 HealYou 主平台，強調溫暖、療癒、私密感
  • 語音為主要輸入，UI 需配合錄音狀態設計（靜音 / 錄製中 / 處理中）
  • Reflection：錄音中偵測到負面情緒時，過去感恩語音的文字靜靜淡入 transcript 區域（opacity fade-in），無彈出式 UI。iOS 實作版應以音訊播放取代文字顯示
  • App 是 iOS 獨立產品，需考慮 native iOS design pattern（Safe Area, Dynamic Type 等）
  • 視覺動畫以 Kyle 的 prototype 為準，工程師直接參照實作，不需重新設計視覺方案
